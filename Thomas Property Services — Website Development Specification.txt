# Thomas Property Services — Website Development Specification

**Version:** 1.0  
**Status:** Approved discovery requirements, pending brand assets and final deployment configuration  
**Domain:** thomaspropertyservices.uk  
**Project objective:** Design and develop a professional, conversion-focused website for Thomas Property Services, a property maintenance and improvement business operating across Cheshire and surrounding areas.

---

## 1. Project instructions for Codex

Act as an experienced frontend developer, UX designer and technical SEO specialist.

Build a production-quality, responsive, multi-page business website using semantic HTML5, CSS3 and vanilla JavaScript. Do not introduce React, Next.js, databases, CMS platforms or unnecessary third-party libraries.

Prioritise:

1. Generating genuine customer enquiries and quotation requests.
2. A premium and trustworthy visual identity.
3. Excellent usability on mobile devices.
4. Fast loading, accessibility and maintainability.
5. Consistent branding across every page.
6. Local SEO and search-engine discoverability.
7. Secure enquiry processing.
8. Minimal recurring operating costs.

The website should be a working implementation, not merely a visual mock-up.

**Important constraints:**

- Do not invent business history, qualifications, accreditations, awards, reviews, project examples or guarantees.
- Preserve all confirmed business information.
- Use clearly identified configuration variables or development placeholders for missing information.
- Never publish invented customer testimonials.
- Never present stock photography as work completed by Thomas Property Services.
- Do not deploy to the live business domain without explicit approval.
- Keep secrets and API credentials out of frontend code and the Git repository.
- If an integration requires external account configuration, implement the code and document the setup without pretending the integration is already active.

## 3. Brand identity and design system

### 3.1 Design direction

The chosen direction is **Premium Craftsmanship**.

The website must be:

- Professional and refined.
- Visually consistent with the existing company logo, business cards and workwear.
- Modern but not excessively minimalist.
- Approachable rather than intimidating.
- Premium-looking without implying that the company is unusually expensive.
- Strongly focused on practical customer actions.

### 3.2 Colour palette

Existing brand colours are blue, white and gold.

Use this provisional palette until the actual logo is supplied:

| Colour | Hex | Usage |
|---|---|---|
| Deep navy | #172C46 | Navigation, hero backgrounds, headings |
| Warm gold | #C4A15B | Accents, icons, primary CTA treatment |
| Soft white | #F7F6F2 | Page backgrounds |
| White | #FFFFFF | Cards, backgrounds and reversed text |
| Dark text | #202B36 | Body copy |

These are temporary design tokens. The final palette must be sampled from the provided brand assets, with adjustments where necessary to maintain readable colour contrast.

Define colours as CSS custom properties. Do not scatter hardcoded colour values throughout the stylesheets.

### 3.3 Typography

Use a refined and legible combination of heading and body typefaces.

Prefer locally hosted or system fallback fonts to minimise layout shifts and third-party requests.

Establish a consistent typographic scale for:

- Hero headings
- Section titles
- Service headings
- Body copy
- Small supporting text
- Form labels
- Navigation

Maintain sufficient contrast, generous line-height and comfortable reading widths.

### 3.4 Visual treatment

Use:

- Large, carefully cropped service photographs.
- Generous spacing.
- Well-organised content sections.
- Subtle shadows and restrained borders.
- High-quality service cards.
- Clear typographic hierarchy.
- Strong but tasteful gold accents.
- Subtle hover transitions and smooth movement.

Avoid:

- Excessive animations.
- Autoplay videos.
- Busy background patterns.
- Unnecessary sliders.
- Large JavaScript dependencies.
- Generic-looking template layouts.

Respect `prefers-reduced-motion`.

### 3.5 Logo and imagery

The existing company logo will be provided separately.

Until supplied, use a clearly marked temporary text-based brand identity.

At launch, use appropriately licensed commercial imagery for services where genuine project images are unavailable. Record image sources and licence details.

Do not create a fictional completed-work portfolio.

All major images should have appropriate alt text, responsive sizes, optimised formats and suitable dimensions.

## 7. Quotation request system

This is one of the website's most important features.

### 7.1 UX requirements

Create a short, mobile-friendly form with optional additional information.

**Required fields:**

- Full name
- At least one contact method: email address or telephone number
- Service required
- Short description of the work

**Optional fields:**

- Second contact method
- Property postcode
- Preferred start date or timeframe
- Additional details

No customer photo uploads are required.

An email address is necessary for an automated email acknowledgement. If the customer supplies only a phone number, do not falsely promise an email acknowledgement.

### 7.2 Service options

Provide:

- Painting and Decorating
- Gloss Work and Wood Finishing
- Property Improvements
- Jet Washing
- One-off House MOT
- Ongoing Property Maintenance
- Other / Not Sure

### 7.3 Form behaviour

- Use accessible labels and informative error messages.
- Validate fields on both client and server.
- Prevent accidental duplicate submissions.
- Show clear loading, success and failure states.
- Display a thank-you confirmation only after successful submission.
- Include an easily accessible retry method for failures.
- Preserve typed content where practical after a recoverable error.
- Provide a telephone fallback if submission is unavailable.

### 7.4 Confirmation text

Suggested successful submission message:

**Thank you for your enquiry.**

Your message has been received. We aim to respond within 48 hours.

For a more urgent enquiry, telephone 07410 928465.

Do not show this confirmation if the server has not accepted the enquiry.

### 7.5 Notifications

On a successful submission:

1. Send a formatted enquiry notification to `thomaspropertyservicesuk@gmail.com`.
2. If a customer email is available, send an automatic acknowledgement.
3. Record a successful quote conversion event where supported.
4. Do not send duplicate notifications during normal request retries.
5. Record server-side errors without unnecessarily logging personal information.

### 7.6 Suggested email architecture

Preferred infrastructure:

- Cloudflare Pages Functions for a secure server-side endpoint.
- Resend for transactional emails.
- Cloudflare Turnstile for spam and bot protection.

Keep API credentials in environment variables or server-side secrets.

Never call the email provider directly from browser JavaScript with a secret API key.

Verify Turnstile tokens server-side.

Use a verified sending domain or subdomain for outbound mail. Deliver business notifications to the existing Gmail address.

Configure domain authentication as required by the email provider.

If these integrations cannot be configured, clearly document missing steps. Never simulate successful email delivery in production.

### 7.7 Privacy and security

- Collect only necessary customer information.
- Provide a privacy notice explaining enquiry-data use and retention.
- Include suitable spam and rate-limit protections.
- Validate input lengths and formats.
- Safely handle user-supplied text.
- Avoid unnecessary personal-data storage.
- Do not publish personal information in GitHub.
- Use HTTPS for all production traffic.
- Ensure any analytics or cookies are configured consistently with applicable UK privacy requirements.

## 14. Accessibility and performance

Target WCAG 2.2 AA accessibility where applicable.

Implement:

- Semantic landmarks.
- Keyboard-accessible navigation.
- Visible keyboard focus.
- Accessible forms.
- Correct headings.
- Adequate colour contrast.
- Touch-friendly controls.
- Descriptive alternative text.
- Reduced-motion support.
- Responsive layouts without horizontal overflow.
- Appropriate mobile font sizes.

### Performance targets

On representative mobile connections, aim for:

- Largest Contentful Paint no more than 2.5 seconds.
- Cumulative Layout Shift no more than 0.1.
- Interaction to Next Paint no more than 200 ms.
- Lighthouse Performance and Accessibility scores of at least 90 under the defined test conditions.

Treat these as measurable performance targets, not guaranteed results.

Prioritise efficient images, minimal JavaScript and avoiding render-blocking resources.
